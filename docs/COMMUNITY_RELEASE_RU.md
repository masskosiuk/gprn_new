# Обновление Онлайн-Сообщества

Рабочий сайт: https://photoapp.metarp.top. Каталог на сервере: `/opt/gprn`.
Новые данные хранятся в PostgreSQL, обложки и вложения в S3/MinIO.
Ни один из новых разделов не использует localStorage как базу публикаций.

## Что Добавлено

- Лента с фото/видео, жанрами, датами, городами и синхронной фильтрацией карты.
- Мероприятия, дискуссии и поиск с отдельными очередями модерации.
- «Открыть дискуссию» у опубликованных работ и товаров: оригинальная
  обложка, проверенная сервером ссылка, вопрос/претензия, отправка на модерацию.
- Жалобы и предложения с закрытыми вложениями, данными отправителя,
  ответом в аккаунт и ссылкой для ответа через почтовый клиент администратора.
- Комментарии к фото, видео и публикациям досок, упорядоченные по текущему
  рангу автора, затем по дате. Удаление автором или модератором.
- «Взаимодействовать» в профиле автора. Сообщения и запросы доставляются
  в серверные уведомления; оттуда можно открыть профиль отправителя и ответить.
- Категории моделей и общий каталог фото, видео, пресетов и LUT.
- Все категории админки свёрнуты по умолчанию.

## Выкладка

Сначала передайте обновлённые исходники в `/opt/gprn` утверждённым способом.
Не переносите `.env`, `node_modules`, `dist`, `.next` и `.git` с компьютера.
Не удаляйте volumes и не пересоздавайте секреты.

Подготовлен архив `gprn-community-2026-10-09.tar.gz` без секретов и кэшей.
Его можно передать через WinSCP в `/opt/gprn/releases/`, затем распаковать
в **PuTTY / SSH-терминале сервера**:

```bash
tar --no-same-owner -xzf /opt/gprn/releases/gprn-community-2026-10-09.tar.gz -C /opt/gprn
```

Архив содержит исходники без `.env.production`, поэтому серверные настройки
не перезаписываются. Архив и резервная копия БД остаются для отката и проверки;
это сохраняемые артефакты релиза, не фоновые инструменты.

Выполните в **PuTTY / SSH-терминале сервера**:

```bash
cd /opt/gprn && \
umask 077 && \
mkdir -p backups && \
docker compose --env-file .env.production -f docker-compose.production.yml exec -T postgres pg_dump -U gprn -d gprn -Fc > "backups/pre-community-$(date +%Y%m%d-%H%M%S).dump" && \
docker compose --env-file .env.production -f docker-compose.production.yml build api && \
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps migrate && \
docker compose --env-file .env.production -f docker-compose.production.yml up -d --no-build --no-deps --force-recreate api web worker
```

Продолжайте только после успешного применения всех миграций, включая
`0011_community` и `0012_discussion_source_covers`.
Цепочка команд останавливается при ошибке резервного копирования, сборки или миграции.
Она добавляет таблицы и поля, не удаляет аккаунты, материалы и старые комментарии.

При последующих обновлениях также запускайте `run --rm --no-deps migrate`
перед пересозданием API. Флаг `up --no-deps` пропускает зависимость `migrate`:
новый образ может требовать ещё не применённую миграцию из предыдущего релиза.
Успешный ответ `/health` сам по себе не подтверждает совместимость схемы БД.

## Ошибка 500 В Разделах Сообщества

Если после обновления API мероприятия, дискуссии, поиск и последние публикации
возвращают 500, сначала проверьте наличие поля из миграции `0012`.
Следующая команда в **PuTTY / SSH-терминале сервера** только читает схему БД:

```bash
cd /opt/gprn && \
docker compose --env-file .env.production -f docker-compose.production.yml exec -T postgres psql -U gprn -d gprn -Atc "SELECT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_schema='public' AND table_name='community_posts' AND column_name='sourceCoverUrl');"
```

Результат `f` означает, что поле отсутствует. В уже собранном образе есть
миграция, добавляющая только `community_posts.sourceCoverUrl`; для её применения
повторная сборка, пересоздание контента и демо-наполнение не нужны.
Запускается кратковременный одноразовый контейнер Prisma с доступом к рабочей БД;
`--rm` удаляет его после завершения, фонового мониторинга и автозапуска нет.

```bash
cd /opt/gprn && \
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps migrate
```

После успешной миграции повторите запрос мероприятий из раздела проверки ниже.
Если поле уже существует (`t`) или миграция завершилась с ошибкой, не выполняйте
`migrate reset`, `db push --accept-data-loss` и не удаляйте тома. Нужна отдельная
диагностика причины 500 по серверным журналам; не публикуйте секреты и `.env.production`.

## Демо-Контент

Предварительно должны существовать демо-мастера, демо-батлы и демо-челленджи.
Существующий контент сайта повторно создавать не требуется.
Следующие команды запускают ограниченные одноразовые контейнеры:
одно ядро, 768 МБ, принудительное завершение через 900 секунд.
Общее имя контейнера запрещает одновременный повторный запуск.
`--rm` удаляет контейнер по завершении; автозапуска нет.

В **PuTTY / SSH-терминале сервера**:

```bash
cd /opt/gprn
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps --name gprn-community-maintenance seed-community
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps --name gprn-community-maintenance seed-product-covers
docker ps -a --filter 'name=^/gprn-community-maintenance$' --format '{{.Names}} {{.Status}}'
```

Последняя команда должна вернуть пустой вывод. Не удаляйте другие контейнеры.
При прерывании SSH задача всё равно ограничена собственным `timeout`.
Если получен таймаут, дождитесь удаления контейнера и повторите ту же команду:
успешно сохранённые карточки не будут созданы повторно.

`seed-community` создаёт 14 общих демо-публикаций: 6 мероприятий,
4 дискуссии и 4 объявления поиска. Они явно отмечены как примеры,
а не реальные события, заказы или обвинения. Повторный запуск не изменяет
решения модерации, тексты, даты и удалённые демо-публикации.

`seed-product-covers` обновляет только управляемые демо-обложки версии v1,
сохраняя товары, цены, названия и продаваемые файлы. Пользовательские
обложки и чужие карточки не перезаписываются. Палитры вычисляются
по реальным пикселям обработанных обложек. Прежние обложки сохранены
в хранилище как резервные; автоматического удаления нет.

Источники иллюстраций: [Lorem Picsum](https://picsum.photos/),
[Unsplash](https://unsplash.com/license). 34 отдельных источника и авторы
зафиксированы в `packages/domain/src/demo-product-covers.ts`.
Это иллюстрации демо-товаров, не фотографии, предлагаемые к продаже.

## Проверка Рабочего Сайта

В **PuTTY / SSH-терминале сервера**:

```bash
(
ulimit -t 10 -v 262144 || exit 1
timeout -s KILL 15 curl --fail --silent --show-error --connect-timeout 5 --max-time 10 'https://photoapp.metarp.top/api/v1/health'
timeout -s KILL 15 curl --fail --silent --show-error --connect-timeout 5 --max-time 10 'https://photoapp.metarp.top/api/v1/community/posts?kind=EVENT'
timeout -s KILL 15 curl --fail --silent --show-error --connect-timeout 5 --max-time 10 'https://photoapp.metarp.top/api/v1/digital-products?kind=PRESET'
)
```

Откройте `/ru/feed`, `/ru/events`, `/ru/discussions`, `/ru/search`,
`/ru/marketplace`, `/ru/suggestions` в двух разных браузерах.
Проверьте одобрение публикации администратором и её появление у второго
пользователя, приватность чужих вложений, ответы и ссылки на оригиналы.
Проверьте светлую/тёмную тему и узкий экран.

## Pro И Платежи

Pro хранится отдельно от ранга фотографа (`profiles.proUntil`).
Администратор с правом `user:admin` назначает срок в карточке аккаунта.
Публикация мероприятий требует действующего Pro. Дискуссии и поиск
доступны бесплатно раз в 72 часа в каждом разделе, с Pro без дневного лимита.
Удаление или отклонение публикации не сбрасывает период ожидания.
Есть дополнительные краткосрочные ограничения против спама.

Автоматическая оплата подписки, защищённые сделки и внешний платёжный
провайдер не входят в эту выкладку. Нажатие пункта «Защищённая сделка»
не создаёт фиктивный платёж и не обещает удержание денег.
Автоматическая отправка email также не подключалась: ответ приходит
в аккаунт, а email доступен администратору для ответа своим почтовым клиентом.
