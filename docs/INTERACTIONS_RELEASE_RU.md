# Переписка, взаимодействия и цены студий

## Изменения

- `/ru/interactions`: сообщения, запросы на съёмку, оценку и менторство, история заказов, обращения в администрацию и собственные дискуссии. Ссылка находится в шапке авторизованного пользователя.
- Диалоги, сообщения и статусы сохраняются в PostgreSQL. Доступ есть только у двух участников, без административного обхода для чтения личных сообщений. Отправка ограничена 60 сообщениями в час на пользователя.
- Получатель может принять или отклонить запрос. Участники могут закрыть диалог. После закрытия новое обращение создаёт новый диалог, сохраняя старую историю. Эти действия не проводят платежи и не меняют рейтинг.
- Миграция `0013_interactions` создаёт таблицы переписки и восстанавливает ранее отправленные сообщения из уведомлений `MEMBER_MESSAGE`. Существующие уведомления не удаляются. Первоначальным отправителем остаётся автор первого сообщения.
- Формы жалобы, сообщения и дискуссии используют отдельное модальное окно и видимую кнопку «Отправить».
- Счётчик комментариев поступает с сервера, учитывает доступные комментарии и обновляется после изменения списка.
- В карточках студий отображаются цена за час и кнопка заказа. Диапазон цены фильтрует и карточки, и карту; доступна сортировка по возрастанию и убыванию цены.
- Текущий каталог студий демонстрационный, без аккаунтов владельцев. По решению владельца проекта кнопка заказа открывает только форму-пример без отправки, записи в базу, бронирования или оплаты. Платёжный провайдер этим обновлением не подключается.

## Обновление

В PuTTY на сервере. Сначала сделайте актуальную резервную копию PostgreSQL по принятой процедуре. Весь следующий блок можно вставить сразу; `&&` остановит выполнение при ошибке:

```bash
cd /opt/gprn && \
git pull --ff-only && \
docker compose --env-file .env.production -f docker-compose.production.yml build api && \
docker compose --env-file .env.production -f docker-compose.production.yml stop api && \
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps migrate && \
docker compose --env-file .env.production -f docker-compose.production.yml up -d --no-build --no-deps --force-recreate api web worker && \
docker compose --env-file .env.production -f docker-compose.production.yml ps
```

API кратковременно останавливается перед миграцией, чтобы старый код не записал сообщение между переносом истории и запуском новой версии. Не запускайте новый API без успешного применения миграции. При ошибке миграции API останется остановленным: сохраните вывод ошибки для исправления. Повторный запуск сидов не требуется. Сборка `api` создаёт общий образ приложения, используемый также `web`, `worker` и `migrate`.

После обновления откройте «Мои взаимодействия» в двух реальных аккаунтах: отправьте сообщение, ответьте со второго аккаунта, обновите страницы. Проверьте создание жалобы и дискуссии, счётчик комментариев и форму-пример студии (без отправки). Заказы в старом механизме остаются отдельной вкладкой; выполнение финансовых действий зависит от имеющегося кошелька и существующих ограничений платежей.

Локальные проверки API используют подменённые делегаты Prisma. Браузерные проверки используют настоящие React-компоненты с тестовыми ответами API. Применение миграции к production и проверку двух реальных аккаунтов нужно подтвердить после обновления сервера.
