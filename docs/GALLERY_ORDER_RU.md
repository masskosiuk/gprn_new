# Порядок портфолио и общей ленты

Автор может перетаскивать свои серверные работы в портфолио, включая просмотр
своего публичного профиля. Администраторы ADMIN и SUPER_ADMIN могут переставлять
публичные одобренные работы в общей ленте. Модераторы и обычные пользователи
этого права не имеют. У гостей ручки переноса не отображаются.

Перенос выполняется за значок в левом верхнем углу плитки; с клавиатуры:
пробел, стрелки, пробел для подтверждения, Escape для отмены. Пропорции и
мозаичная раскладка изображений сохранены. Во время переноса остальные плитки
не анимируются и не накладываются друг на друга, место назначения выделяется.
При ошибке запроса возвращается предыдущий порядок и показывается сообщение.

`PATCH /api/v1/photos/gallery-order` принимает `scope` (PORTFOLIO или FEED),
`photoId`, `targetId` и `placement` (before или after). Права проверяются на
сервере. Переставляется одна работа относительно другой, поэтому активные
фильтры не удаляют и не перезаписывают скрытые из текущего вида работы.

Порядок хранится в независимых колонках `photos.portfolioPosition` и
`photos.feedPosition`. Общая лента и публичное/личное портфолио читают их
одинаково при каждом запросе, без browser-only сохранения. Перестановка в одном
разделе не меняет другой. Новые работы без заданной позиции идут после уже
расставленных работ; между собой сортируются по дате и ID.

Изменения атомарны, сериализованы advisory lock по области и записываются в
аудит. Меняются только позиции, не фотографии, владельцы, даты публикации,
статусы, оценки, комментарии или права доступа. Запрос ограничен 10 000
работами и транзакцией 15 секунд; позиции обновляются одним параметризованным
SQL-запросом. Больше 10 000 работ приводит к отказу без записи.

## Обновление

Нужна миграция `0017_gallery_order`: два nullable-поля и два индекса. Существующие
данные не удаляются. Образ общий для API, web и worker, поэтому перезапускаются
все три приложения после миграции.

PuTTY на сервере:

```sh
cd /opt/gprn && git pull --ff-only && docker compose --env-file .env.production -f docker-compose.production.yml build web && docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps migrate && docker compose --env-file .env.production -f docker-compose.production.yml up -d --no-build --no-deps --force-recreate api web worker
```

После обновления можно безопасно проверить контейнеры:

```sh
cd /opt/gprn && docker compose --env-file .env.production -f docker-compose.production.yml ps
```
